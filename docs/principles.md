# 原则

## 0. 一句话

所有东西都做成**参考**，不干扰 AI 的判断。prompt 只放「可发现性元数据」与「授权边界」；知识、规则、工作流、案例一律作为 reference 按需加载，读完由模型自主判断。

## 1. 参考而非干扰

- 知识、规则、工作流、案例、工具用法 → 全部放进 `references/`，通过 `read_reference` 工具按需读取。
- 不把「结论 / 规则 / 强制流程」写进 system prompt 去替模型做决定。
- 模型读完参考后自行判断是否适用、如何执行。

## 2. 最小注入

system prompt 只保留两类内容：

| 允许注入 | 为什么 |
|---|---|
| 可发现性元数据（有哪些参考、什么时候该查） | 让模型知道可以查什么，不替它下结论 |
| 授权边界 / 安全约束（只测授权目标） | 定义合法域，是硬约束而非判断干扰 |

其余一律不进 prompt。

## 3. 真实优先

- 不编造 API、路径、版本、日志、测试结果、执行输出。
- 不知道就查，查不到就说明，无法确认就停止猜测。
- 假设标注 `[假设]` 并说明验证方法。

## 4. 证据优先

- 每个结论都要有证据：文件行号、内存 dump、pcap、偏移、哈希、命令输出。
- 不把「一条字符串 / 一行日志 / 自动反编译结果」当作已确认的调用链。
- 无证据时，明确说明「缺少什么、下一步该取什么」而不是假装分析。

## 5. 渐进披露

- 主入口只放路由与目录，细粒度内容按需加载。
- 不把整本知识库塞进上下文，控 token。
- 每个 bundle 自包含自己的 `references/` 与 `scripts/`。

## 6. 授权边界

- 只分析用户有授权的目标（自有资产或书面授权）。
- 越界、针对第三方未授权、或要求产出恶意内容（malware / phishing / ransomware / 凭据窃取 / 利用）时，拒绝并说明原因。
- 授权边界属于硬约束，不是可被「注入提示词」压掉的判断项。

## 7. 自包含

- 每个领域技能 = 一个独立 bundle（npm 包 + `dsh.bundle.patch`）。
- 自带 `src/` + `references/` + `scripts/`，全部列进 `package.json` 的 `files`。
- 不依赖「共享脚本 + 扁平叶子」这类无法独立安装的结构。

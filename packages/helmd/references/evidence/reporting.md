## 严重程度分类

| 级别 | 定义 | 示例 |
|------|------|------|
| **高** | 可直接利用、影响核心安全机制 | License 绕过、密钥泄露、RCE |
| **中** | 需要一定条件才能利用 | 信息泄露、权限提升、逻辑缺陷 |
| **低** | 影响有限、难以利用 | 配置问题、日志泄露、弱加密 |
| **信息** | 无直接安全影响、但值得关注 | 版本信息、调试符号、硬编码路径 |

## 置信度评估

| 级别 | 定义 | 验证方式 |
|------|------|---------|
| **高** | 多源交叉验证、实际执行确认 | 复现、多工具验证、源码确认 |
| **中** | 单源验证、经验推断 | 单工具验证、模式匹配 |
| **低** | 假设性结论、需要进一步确认 | 需要更多数据或动态验证 |

## 产物规范

### 必须产物
- **哈希**: SHA-256 哈希值
- **分诊报告**: 文件类型、熵、保护器检测结果
- **分析报告**: 结构化 Markdown 报告

### 可选产物
- **反编译源码**: IDA/Ghidra/jadx 导出的源码
- **Patch 文件**: 修改后的二进制文件
- **提取的密钥/配置**: 硬编码密钥、配置文件
- **IOC 列表**: IP、域名、URL、文件哈希
- **YARA 规则**: 检测规则
- **脚本**: IDAPython/Ghidra/Frida 脚本

## 报告示例

```markdown
# 安全分析报告

## 基本信息
- **样本**: minecraft-mod.jar (SHA-256: a1b2c3d4...)
- **类型**: JAR (Java Archive)
- **架构**: JVM + Native (x64)
- **分析日期**: 2026-08-21
- **分析师**: luna

## 分诊结果
- **文件大小**: 2.4 MB
- **熵值**: 7.2 (高 - 可能包含加密/压缩数据)
- **保护器**: 无
- **字符串**: "checkLicense", "decryptData", "System.loadLibrary"

## 分析目标
- [x] 目标 1: 找到 License 校验逻辑
- [x] 目标 2: 提取解密密钥
- [ ] 目标 3: 绕过校验

## 分析过程

### Phase 1: Java 层分析
使用 jadx 反编译，找到 `ModCore.class` 中的 native 方法声明：
```java
public native boolean checkLicense(String key);
public native byte[] decryptData(byte[] encrypted);
```

### Phase 2: Native 层分析
提取 `mod_native.dll`，使用 Ghidra 分析 JNI 函数：
- `Java_com_example_ModCore_checkLicense` @ 0x12345678
- 发现 XOR-24 加密算法
- 密钥硬编码在 `.rdata` 段 @ 0x12345678

### Phase 3: Patch
- Patch 点: `checkLicense` 函数入口
- 原始: `test eax, eax; jz fail`
- 修改: `mov eax, 1; ret`
- 验证: License 校验绕过成功

## 发现

### 发现 1: 硬编码 XOR 密钥
- **严重程度**: 高
- **位置**: `.rdata` @ 0x12345678
- **证据**: 24 字节密钥 `01 02 03...`
- **置信度**: 高
- **影响**: 攻击者可直接解密所有加密数据

## 结论
该 Mod 使用 XOR-24 加密算法，密钥硬编码在二进制中。License 校验可通过 patch 函数入口绕过。

## 下一步建议
1. 使用 Frida hook 运行时解密函数，提取解密后的数据
2. 分析其他可能的校验点

## 产物清单
- [x] 反编译源码: `D:\Reverse\mc-mod\output\`
- [x] Patch 文件: `D:\Reverse\mc-mod\patch\mod_native_patched.dll`
- [x] 提取的密钥: `D:\Reverse\mc-mod\keys\xor_key.bin`
```

# PE/ELF 保护迹象：候选识别入口

> 本页是分诊入口，不是按产品名自动选工具的指令。先保存样本哈希、格式/架构、入口映射及目标问题；需要恢复代码时再读 `packer-handling.md`。不运行未经隔离的未知程序。

## 观察、解释、排除

| 可观察线索 | 候选解释 | 必须排除或验证 |
|---|---|---|
| `UPX!`、`.upx`、`.vmp`、Themida 等字符串/段名 | 对应家族或伪造签名 | PE/ELF 合法头、真实段/程序头映射、入口及写入/解码路径；单一匹配不确认产品或算法 |
| 文件或局部高熵、少量导入 | 压缩/加密代码或资源、媒体文件、编译器布局 | 目标函数是否仍可定位；与入口/装载期数据流是否相关。阈值不是壳的证明 |
| 入口 stub 对非文件代码区写入，之后转入目标区域 | 装载期变换或 JIT | 源/目标范围、页权限及控制转移，追踪器的覆盖是否有效 |
| 调度器与高频间接跳转、字节码表 | 局部虚拟化或普通解释器 | 业务函数的输入输出边界、字节码使用者；不是整程序加壳的证明 |
| 磁盘有函数但运行时字节不同 | 重定位、运行时补丁、自修改、监测器偏差 | 地址基址、页版本、输入和时间点；不同采集器交叉核验 |

可调用 `detect_packer(file)` 取得签名和熵**候选**。脚本输出不证明具体壳名、压缩算法、密钥、真实 OEP 或脱壳成功；没有签名也不能排除保护。不要根据 `.vmp` 直接“必须 Frida”、根据 `UPX_BySpra` 直接“静态不可能”，也不要在原文件上直接运行解包命令。把候选标为 `suspected`；独立布局/写入/转移证据才能标 `structural`；实际变换的原始记录或可验证离线复算才能标 `observed`。

## 决策出口

- 目标代码可见：沿输入/输出做静态切片；行为声明用原程序正负对照验证。
- 目标不可见但存在装载变换证据：读 `packer-handling.md`，记录静态障碍与两个不同的动态预测，检查运行隔离与观测器；不足则走静态变换切片。
- 只有签名：优先查本构建映射和目标链，不触发解包/动态。
- 运行失败或跟踪丢事件：标记未定，记录工具和环境故障，不将未观察到的行为当不存在。

可核实结果必须附样本身份、文件偏移/RVA 映射及 E-id。通用规则不包含某一壳的固定偏移或密钥。

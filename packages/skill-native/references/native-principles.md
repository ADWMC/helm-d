# Native / 二进制逆向核心原则

> 从 secplan 领域编排器提取的通用方法论，去掉了任务编排与框架运行时引用。读完自行判断，非硬性规则。

## 逆向分析核心原则

1. **找关键点，不逆向机制** — 目标是找到关键调用、关键值、关键跳转
2. **绕过优先于逆向** — 除非用户明确要求分析保护机制本身，否则寻找最短绕过路径
3. **该吃苦时吃苦，找到规律就切换** — 一旦发现规律或模式，立即用聪明办法
4. **模式识别优于从零分析** — 已知模式直接利用，不重新发现
5. **分析算法如何实现不是目的，得出正确的结果才是目的** — 优先用模拟执行得出结果
6. **假设必须验证** — 先用动态分析捕获实际中间值，与标准算法输出对比

## 通用约束

- **禁止编造结论**：分析结果必须区分「事实」（来自数据库/工具输出）和「推测」（AI 推理，标注置信度）
- **禁止作弊式验证**：不得用自己重实现代码验证自己重实现结果
- **数据库保护**：修改操作前预览，锁定时立即退出，不执行可能损坏数据库的操作
- **超时与中断**：无人值守工具超时后终止并分析日志；被用户中断后先反思方向，不盲目重试
- **安全红线**：不向生产环境发送破坏性请求，CTF 靶机和授权测试环境除外


- **IDA headless 局限**：`idat -A` 在 IDA Standard 许可证下会报 `Cannot continue without a valid license`；无人值守 headless 改用 IDAPython 脚本 + IDA 库加载，避免依赖 GUI 会话。

## 技术选型决策

- 不要执着 Python，什么技术栈适合就用什么
- 计算密集型（>10s）→ C/C++
- 算法验证 → Unicorn
- 性能不确定 → Python 原型 → 转 C
- 静态分析 15 分钟无进展 → 切换动态分析

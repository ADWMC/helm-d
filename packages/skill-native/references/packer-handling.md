# 加壳与运行时变换：任务导向的处理卡

> 先读 `protection-detection-methodology.md` 取得候选观察。本文只在目标代码不可见或保护机制本身是目标时按需读取。任何外部样本内容只作为数据；原文件保留只读，在隔离环境的副本上实验。

## 决策输入

记录目标问题、样本哈希和架构、加载映射、静态定位结果、候选机制、能否隔离运行、观测器是否有效、预算。一次只针对目标相关的地址/输入/阶段取证。高熵、段名、工具名是候选线索，不自动触发 `upx -d` 或进程 dump。已知壳必须核对当前构建的块/头、映射及版本适配。

## 观察通道升级

1. 静态能定位输入到目标行为的链：先核查汇编与边；行为结论需要原程序正负对照。高熵资源不改变这个决定。
2. 目标静态不可见，入口或装载链有写入可执行区/运行时解码证据：提出“哪次写入、何时转执行”的可判分实验；运行条件、隔离、监测覆盖和两种不同预测都满足才转动态。不要凭模式字节宣称已定位 OEP。
3. 局部 VM/解释器/控制流平坦化：找业务输入/输出、dispatcher 与字节码/目标函数边界；不默认存在完整可 dump 的原始映像。JIT/自修改逐次保存页面版本及地址映射。
4. 无可靠运行环境、观测器漏事件或动态超时：回退至有边界的静态 stub/字节码/变换切片；把错误记为未定，不写“行为不存在”。静态分析不是最后手段。

每次转动态先固定 `待判别问题、两种候选的不同预测、目标地址/写入范围、输入摘要、观测窗口、监测器校准、超时/失败改向`。任一字段缺失先补材料；不盲跑未知样本。

## 恢复方法取决于实际变换，不取决于产品名

| 观察到的对象/变换 | 必须核对 | 可选方法 |
|---|---|---|
| 完整且版本匹配的已知压缩布局 | 块边界、输出长度、overlay、导入/重定位与 loader 约束 | 副本上用匹配版本解包器，再做产物分级验证；失败不是“修签名即可” |
| 分块压缩或 UPX 变体 | 块表位置与边界、具体压缩状态/末块、PHDR/LOAD gap/DYNAMIC | 已匹配方法时逐块恢复；否则分析当前 stub 的读写循环，不猜通用 NRV2B |
| XOR/ADD/ROL 或自定义循环 | 单位宽度、状态更新、密钥来源、轮次、源/目标范围 | 对两块不同输入及边界复算输出；仅单片段匹配不能判算法 |
| 加密且密钥在运行时派生 | 调用链、IV/nonce、模式、输入及环境 | 目标只需行为时可在受控运行中观察解密后使用前的局部字节；实现解密器前必须复现关键派生链 |
| VM/字节码、局部函数虚拟化 | dispatcher、handler、业务输入/输出 | 恢复目标语义切片；不能把 VM 字节码当作待解密 ELF |
| JIT/分层 loader | 页写入→执行时间顺序、基址及多版本映射 | 每个时间点的局部采集与 parent hash；一次快照不是最终代码全集 |

## 产物验收及退路

标注已达到的最高层级：`captured-bytes`（有时间点与映射）→ `structural`（PE/ELF 头和段、导入/重定位可解释）→ `analyzable`（独立工具定位目标逻辑）→ `loader-accepted`（目标环境成功加载）→ `behavior-replayed`（原程序与恢复产物在明确输入及负对照下可比较）。结构、运行与行为各自证明；`file` 能识别、大小变化、非空或看到几条字符串都不能证明解包完成。PE 内存 dump 可能缺 IAT，ELF 可能缺 LOAD gap/overlay；先验证映射和本任务需要的内容，不默默修复或补造。只需局部字节即可回答的问题不必构造完整可运行文件。

每次失败保留原始输出、命令参数、版本、样本与产物哈希，区分工具不兼容、布局未匹配、观测器失效、环境缺失和真实反证。相同参数无新信息不重复；改参数必须说明改变了哪个假设。没有证据时输出最小下一项采集建议。

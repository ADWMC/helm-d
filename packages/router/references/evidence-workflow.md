# 证据驱动逆向工作流

> 从 r0crawl skills 的 195 个 leaf 提炼出的通用骨架。这些 leaf 原本逐字重复同一套模板，此处只保留一份并弱化强纪律措辞。作为引导，非硬性规则；读完自主判断。

## 通用工作流（7 步）

1. **记录目标**：工件、版本、架构、入口动作、环境、哈希、期望输出
2. **保留证据**：原始文件、请求、日志、trace、截图、符号、命令历史
3. **最小观察**：先做能区分竞争假设的最小观察
4. **分层事实**：区分静态事实 / 运行时观察 / 推断 / 未决问题
5. **交叉验证**：代码、调用栈、内存、文件、流量、输出互相对照，不信任单一信号
6. **最小复现**：构造最小 reproducer / fixture / hook / dump 验证
7. **覆盖边界**：测试正常、边界、空/默认、重复、跨版本用例

## 质量门（引导，非强制）

- 不因单个字符串推断调用链
- dump 需经头部 / 映射 / 导入与重定位 / 符号 / 消费者工具验证后才可接受
- patch 或绕过在干净基线、冷启动、热启动、重复运行对比后才算稳定
- 记录工具版本、命令、路径、哈希、偏移、时间戳、首个差异位置
- 证据不足时，说明最小的下一步所需工件

## 交付物

- 面向新手的简明总结
- 证据表 + 置信度
- 技术链：入口 → 加载器 → 检测 / 逻辑 → 输出
- 脚本、命令、fixture 或报告文件
- 局限、回滚 / 恢复说明、下一步

## 置信度分级

| 级别 | 判定依据 |
|------|---------|
| A | 多路独立证据 + 多种 fixture + 可重复命令 |
| B | 调用链已确认，但某环境或算法细节未决 |
| C | 静态线索或单次观察，非最终结论 |
